# Importing an export into Paperclip

Save a preset, open its **Export** tab, select **Paperclip**, and download the company-package ZIP. The same files are generated in `exports/paperclip/<id>/`. Each package describes one agent; review the export's omissions before importing it into Paperclip.

ASM prepares the files and never contacts Paperclip. The API procedure below targets Paperclip [2026.1106.0](https://github.com/paperclipai/paperclip/releases/tag/v2026.1106.0). Check the running Paperclip version before using it; version-specific observations below refer to that release. The package format is documented in Paperclip's [company specification](https://github.com/paperclipai/paperclip/blob/master/docs/companies/companies-spec.md).

| File | Holds |
| --- | --- |
| `COMPANY.md` | The package's slug, name and description. |
| `agents/<id>/AGENTS.md` | The agent's name, title, role `general` and skill names; the body is the preset's Instruction. |
| `.paperclip.yaml` | Role `general`, heartbeat off, and `metadata.agentStackManagerPackageId` and `agentStackManagerRevision`. No adapter and no permissions. |
| `skills/<key>/SKILL.md` | One stub per skill: repository, path and branch, no commit. |

ASM writes skill stubs for GitHub repositories with a tracking branch. The Paperclip skill library also supports importing skills from approved local paths. [Paperclip skills documentation](https://github.com/paperclipai/paperclip-docs/blob/main/docs/guides/org/skills.md#3-import-from-a-local-file-or-folder)

The export assigns role `general` and no permissions or adapter. Whoever imports configures these in Paperclip (steps 4 and 5 below). Captured installed, enabled and selected states for other apps cannot be carried by this company package; the export reports them as omissions.

## Import a preset

Only the board and CEO agents may import a company package ([companies.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/routes/companies.ts#L364-L378)).

1. **Create a skill source for each repository and branch the stubs name.** An import creates no source (observed on 2026.1106.0), and Paperclip refuses a remote skill that is not pinned to a commit ([company skill policy](https://github.com/paperclipai/paperclip/blob/master/doc/company-skill-policy.md)), so the stubs only say which sources to create. Call `POST /api/companies/{companyId}/skill-sources/discover` with `repositoryUrl` and `trackingRef` (the branch), then `POST /api/companies/{companyId}/skill-sources` with the `commitSha` it returned and `selectedPaths` set to `<path>/SKILL.md`, or `SKILL.md` when the path is `.`. Reuse a source that exists. A source re-checks its branch every five minutes unless its automatic updates are paused ([PRODUCT.md](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/doc/PRODUCT.md#L157-L162)). Paperclip names each skill `github/<repositoryId>/<hash>/<slug>`, where the slug is the skill's folder name, or the repository name for a skill at the root (observed on 2026.1106.0).
2. **Import the agent without `skills/`.** Send `COMPANY.md`, `agents/<id>/AGENTS.md` and `.paperclip.yaml` as inline files, with `include` set to agents only and `target` to the existing company. The stubs would make the import fail with a 422 (observed on 2026.1106.0). The board uses `POST /api/companies/import`. A CEO agent uses `POST /api/companies/{companyId}/imports/apply` and passes `adapterOverrides` for the agent's slug: the export has no adapter, and this route refuses the `process` adapter Paperclip [falls back to](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/services/company-portability.ts#L3270) ([company-portability.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/services/company-portability.ts#L3678-L3680)).
3. **Check the skills.** The skill names in `AGENTS.md` become the agent's desired skills and resolve by slug to the skills of step 1 (observed on 2026.1106.0). A skill whose source was created later is attached with `POST /api/agents/{agentId}/skills/sync`, `{"mode": "add", "desiredSkills": [...]}`.
4. **Set the adapter**, and in it any MCP server the preset has.
5. **Set the role and rights the company needs.** Give the role `ceo` to an agent that leads the company, and the right to create agents to an agent that hires, such as AI Resources.

An agent without import rights hires instead: the sources of step 1, then `POST /api/companies/{companyId}/agent-hires` with the package's name, title, role, metadata, skills (`desiredSkills`) and an adapter, and with the `AGENTS.md` body inline as `instructionsBundle.files["AGENTS.md"]` ([agent.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/packages/shared/src/validators/agent.ts#L86-L103); the hire runs on that file, observed on 2026.1106.0), then step 3. The other way is the same call without `instructionsBundle`, then the write of update step 1 below: a hire on an adapter that takes an instructions bundle already has Paperclip's default `AGENTS.md` ([agents.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/routes/agents.ts#L2415-L2446), [hire](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/routes/agents.ts#L4560-L4563)), so `baseRevisionId` is that entry's revision id, not `null`. A hire gets the right to create agents unless that call's `permissions` sets `canCreateAgents` to `false` ([agent.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/packages/shared/src/validators/agent.ts#L15-L22), [agent-permissions.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/lib/agent-permissions.ts#L69-L76), [authorization.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/services/authorization.ts#L2615)), so a role that does not hire is sent `canCreateAgents: false`. The hire call has no field that takes away the right to create skills on this release: a standard hire gets the `skills:create` grant when it is activated ([agent-hiring.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/services/agent-hiring.ts#L61-L67)), and the company's skill policy decides which skill writes it may make ([company-skills.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/routes/company-skills.ts#L225-L266)). The hiring agent needs the right to create agents, given in Paperclip by whoever set the company up. The AI Resources preset's Instruction follows this path.

## Apply a preset update

When `agentStackManagerRevision` in the new export differs from the agent's metadata, update the agent in place. A second import that replaces the agent sets its adapter from the package and clears its reporting line, since the export names no manager ([company-portability.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/services/company-portability.ts#L5680-L5682), [update](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/services/company-portability.ts#L5700-L5704)), and the CEO route refuses `replace` ([companies.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/routes/companies.ts#L1166-L1168)).

1. Read the entry with `GET /api/agents/{agentId}/instructions-bundle/file?path=AGENTS.md`; the answer carries its revision id as `revision.id` ([agents.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/routes/agents.ts#L5103-L5133), [answer](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/routes/agents.ts#L787-L793)). Then `PUT` the same route with `path` `AGENTS.md`, the new body as `content` and that id as `baseRevisionId` ([agent.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/packages/shared/src/validators/agent.ts#L35-L41)). Without `baseRevisionId` the write is refused with a 422 `INSTRUCTION_BASE_REQUIRED` ([agents.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/routes/agents.ts#L5146-L5147); observed on 2026.1106.0), and with an id that is not the current one with a conflict, `INSTRUCTION_REVISION_CONFLICT` ([agent-instruction-revisions.ts](https://github.com/paperclipai/paperclip/blob/v2026.1106.0/server/src/services/agent-instruction-revisions.ts#L285-L293)).
2. Sources for any new repository or branch, as in step 1 above.
3. `POST /api/agents/{agentId}/skills/sync` in `add` mode for new skills and `remove` mode for dropped ones.
4. `PATCH /api/agents/{agentId}` with the new `metadata.agentStackManagerRevision`, last and only once the steps before it succeeded, since that value is what says the agent is up to date.

## What the export leaves out

`python -m asm_app export` and the dashboard's Export tab list every component the export does not carry, with the reason. They stay in the APM package.

- **MCP servers**: the company package has no MCP entry. Set them in the agent's adapter after import.
- **Hooks and plugins**: the company package has no entry for them.
- **A further APM instruction**: Paperclip takes one Instruction per agent; merge it into the preset's Instruction.
- **Skill files Paperclip rejects**: its [skills store guide](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/skills-store.md) lists what an import omits.
